# Spec KB 采用文档式存储，条文化作为后续增强

Spec KB 的核心诉求是「可上传已有规范文档、可留空」：现实中的规范都是自由 Markdown，而条文式（结构化规则条目 + 稳定规则 ID）需要一套入库预处理子系统（抽取、人工确认、ID 维护），不应挡在核心验证之前。故决定：文档为存储形态，rationale 以「文档名 § 节名」引用；条文化（按条启停、精确追溯）推迟为后续增强。

## Considered Options

- 条文式：每条规则稳定 ID + 严重度，追溯精确，但入库预处理成本高
- 混合式：文档存储 + LLM 抽取生成条文索引，两头兼顾但复杂度最高
- 文档式（选定）：零入库成本，引用人类可读

## Consequences

- 每个文档顶部建议 3-5 行「TL;DR 不可违反清单」——专家提示词中最有效的规范注入形态
- 语义冲突（多文档互相矛盾）属人工维护责任，系统不做覆盖仲裁，仅按内容 hash 去重
